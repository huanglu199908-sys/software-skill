# 文档审查、修复与交付

## 规则来源分层

下列来源于 2026-10-17 核查。实际申报前重新核实登记机构当前规则，记录网址与日期，不能把本文件视为永久法律清单。

| 层级 | 用途 |
| --- | --- |
| [国家版权局《计算机软件著作权登记办法》](https://www.ncac.gov.cn/xxfb/flfg/bmgz/202410/t20241015_869486.html)第九至十一、十七、二十一条 | 申请表、鉴别材料和证明文件；通常前后连续各30页，不足60页提交全部；程序50行、文档30行的原则及特定情况；A4；名称、权利人与完整性 |
| [上海计算机软件技术开发中心材料说明](https://sscenter.sh.cn/SoftwareCopyrightAgency/index.html) | 页眉页号、结束页、空行、合作开发证明等公开操作说明，不能替代登记机构当前口径 |
| 上游技能的后端/排版规范 | 工程实施约定，例如字号、折行宽度和工具版本，不称为法定唯一格式 |
| 用户参考文件及偏好 | 适用于本次任务的写法与格式，不把旧内容或曾经通过的内部检查当作登记批准证据 |

程序和文档都要判断交存模式。长文档同样不能忽略连续页规则。不要截取不相邻的“最好看页面”冒充连续前后页，也不要为了60页写无用内容。整份恰为60页时前后30页并集就是全份，文件如何分装按受理要求处理。

封面、目录、含图页、结束页要分类核查。不能假称法规明确豁免所有图页/目录；把特殊页面列入报告，结合当前受理要求判断。遇到无法确认的特殊格式明确列为待核查，不把它们静默算成普通正文达标。

## 四层检查

套用样式前先读[默认写法与版式](reference-format.md)，形成参考文件与当前文件的差异表。检查既覆盖“内容真实”，也覆盖“像用户指定的参考文件”：封面、目录、概述与流程模块、正文叙述、图注、页眉页脚、代码编号及显示规则均须逐项核对，不能只通过字体校验就称完成。

### 1. 软件真实性与登记事实

逐项对应功能—源码—测试—真实页面—手册。核对实际版本、登记版本、名称、主体、开发方式与协议的关系。证件待补录不妨碍生成获准的可编辑草稿，但不能称申请资料全部齐备。

### 2. 源码完整性与连续性

冻结有序选材、文件SHA256、编码和提取规则。保留完整源文件，不删除独立注释、说明字符串、尾部括号或引号。提取必须识别原样字符串中的空行语义，不能以全局删除空白的方式验证完整性。

分别报告全项目物理行、选择文件物理/非空行、材料展示行与实测页数。编号不是代码；确定性折行是显示处理，不修改实际源码，不能靠折行夸大程序量或声称达到某种“原创代码规模”。

从最终 DOCX 通过 OfficeCLI 重新读取正文；按明确的文件边界和行映射去除排版行号、合并折行，保留缩进及字符串空白，与冻结源码逐行比较。只删所有空白后的逐字符比较可作初筛，不能代替完整检查。本技能[源码证据脚本](source-evidence.md)支持带映射的核验；无法重建映射时如实报告限制。

前后页模式：先建立完整有序来源和连续抽取范围，再核对实际分页边界和取页连续性。不能以任意重排/挑选文件的结果证明原程序“前后连续”。无需为大型项目保存巨型全量 Word，但须有可追溯的完整排版/取页映射及最终两段核查证据。

### 3. 手册内容与范围

检查章节能否指导真实操作，入口/按钮/状态是否准确，输入限制和异常反馈是否与软件一致。结果数据来自对应截图，历史页面不冒充当前结果。没有实际试验支持时删减性能口号，不扩写成“普遍更快”。

用户要求删除附录时检查：正文附录块、目录条目、书签/交叉引用、普通文字中的指向以及删除后残留空页。不要顺便删除用户正常的术语表、必要边界或磁盘支撑文件。

### 4. 结构与真实排版

- 文件存在且可读；OfficeCLI `validate`、issues 检查；主题、正文、表格、页眉字体与颜色符合本次要求。
- 软件全称/版本在封面、页眉、正文、申请表与文件名一致；页码字段有实际显示值、连续且位置正确。
- 目录页码须与真实章节位置逐项相符；图注与图片同页，封面、目录、含图页、结束页在行数审计中分别列类，不能把正文第一页误当封面豁免。默认样式代码逐页编号1—50，末页允许不足50行；编号不计为源码，换页后不能延续为51。
- 用实际排版引擎复核页数；程序普通页有效行数、手册普通正文页视觉行数逐页记录，不能仅统计 XML 段落数量。
- 表格同行不同单元格的视觉行数不能相加冒充多行；页眉、页脚、空行和行号不当作正文代码行。
- 检查折行、截断、缩进、字号可读性、表格越界、孤立标题、图文错位、图片/图注分离、目录错误和空白尾页。
- 图片挤到下一页造成普通文字页过疏时，先按相关解释调整插图位置或适度等比缩放；不要固定每章都把截图放末尾，也不要用重复说明补行数。最终Markdown、图片位置记录和Word应能对应。
- 渲染覆盖每一页。联系表用于全局检查，文字密集处、边界与疑似缺陷查看原尺寸；首中尾抽查不能冒充全页检查。

无法取得原生分页时说明“结构已查，真实分页待核”，不填估算页数为实测。DOCX 字段缓存可能陈旧，必要时刷新，再重新校验与渲染。

## 修复顺序与复验

先改事实/功能/源码缺漏，再调整文字，最后排版；每轮从缺陷证据出发，不机械跑固定数量轮次。正文过稀优先整理分页与重复空白，只有缺少真实使用说明时才补文字，不为行数制造同义段落。

源码修复要回到真实源文件，不手工编出闭合标记后称“已一致”。生成工具修复不得改变软件算法；确需改产品时重新进入对应验收阶段。

修订前备份与哈希；修订后同步最终代码页数至申请表、相关清单和当前报告。旧版记录保留日期且不作为当前结论。

用户已要求“按指定文件修订”或“据实校正页数”时，在其明确范围内执行并保留差异及授权记录；不把机械页数回填伪装成新事实确认。正式目录只保留当前有效材料，历史Word备份移至analysis中的修订备份目录，避免下载旧文件。不得因此删除用户的无关文件。

预览复用必须同时满足 DOCX 哈希、渲染工具/字体环境与渲染配置一致，有完整页数映射。仅修改时间相同或文件名相同不足以复用。刷新目录或字段后哈希变化，就检查影响并更新预览。

## 审查报告

每个检查项写“通过 / 失败 / 未验证 / 不适用”，附证据路径、文件哈希、工具版本、实际页数、问题与修复。把剩余身份/签章资料与已通过文档检查分开列出。

结论可写“本轮检查项已通过；剩余某字段待补录”。不能写“确保授权”“登记必过”，也不能把公开网页样例或本地源码一致性当作独创性、权属无争议证明。
