# 默认写法与版式

本样式来自用户2026-10-18明确指定的《增量式办公台账数据质量检查软件_操作手册_修订版.docx》及《增量式办公台账数据质量检查软件-代码(全部)_修订版.docx》，采用的是删除附录后的实际Word文件。它是本技能的默认交付偏好，不是登记机构规定的唯一模板。当前用户新给的参考与明确要求优先。

数值见[format-profile.json](format-profile.json)。不依赖原电脑目录，也不捆绑原项目源码、截图、身份信息或协议。拿不到原参考文件时可按本参数制作，但不得称已重新阅读原文件。

## 手册结构与写法

封面独立一页：软件全称、分行的“操 作 手 册”、版本号、开发完成日期、已确认的著作权人。姓名、单位和归属从当前项目申请表读取，不能沿用案例；封面署名表示著作权归属，不等同于开发者名单。参考中分列机构与共同著作权人；当前项目不适合分列时按其真实主体排列。

第二页为目录，标题“目  录”，列出中文序号章名、点引导线和真实页号。首章另起页，使用书签与PAGEREF等可更新字段或经实际分页核对的等效目录；最终字段刷新后再校验和渲染，不能交付0、错误页码或TOC_ENTRY标记。

正文依次组织为：软件概述、说明、功能特点、系统要求、总体流程与模块组成、按实际页面/业务流程展开的操作章节、典型业务流程、常见问题解答、术语表。实际页面数决定章节数，不能照抄案例的“八页、十六章”等数量。概述交代任务与使用者，说明交代输入、结果及必要边界；不要两章重复整段软件介绍。

页面章节以连续段落说明具体事务：何时使用、从哪里进入、填什么或点什么、看到什么结果、异常后如何继续。引用软件真实按钮名称和输入示例，不使用“进入方式：/页面内容：/操作步骤：”字段模板，不堆编号步骤或营销功能列表。问答用“问题：……”及自然回答，术语用简洁对照表。技术细节仅在帮助用户理解结果时出现，完整实验、实现和验收材料留在磁盘。

总体流程配一张真实业务流程图，模块组成配一张能对应已实现软件的说明图。图是解释图，不能冒充界面截图。核心页面使用对应版本的实际运行截图，图注连续编号，写清图中实际状态；示例为合成数据时明确其性质，不借用旧项目界面、结果或截图。

正文通常用12磅宋体，18磅固定行距、段后4磅、首行两字，黑体15磅章标题。系统要求及术语表使用可读的表格；图片通常宽15厘米并保持比例，按页面空间适度调整，不裁掉关键控件或压缩到无法阅读。图片段落与图注保持同页，可将图放在对应解释旁，不必每章末尾集中放图。

默认不含附录、“相关文档”开篇表或设计/测试文件索引，不保留正文和目录中的相关指向。磁盘支撑文件继续保存；用户明确要求另加的资料按其范围处理。

## 代码材料

代码正文9磅Consolas，中文宋体，13.4磅固定行距，无额外段距。A4竖版，页内行号从1到50，每页重新开始；普通页50个有效源码展示行，结束页保留实际剩余行，不补空行或制造源码。行号是排版标记，不是程序量。

这是用户指定的50行版式，必要时可在每50个展示行处设置分页。编号、字号、页边距改变后必须由真实排版引擎检查，不能仅凭分组估算页数。若长行在Word中再次折行导致溢页，先校准显示折行宽度或可用宽度，不能缩成不可读字号、删源码或只改页码数字。

正文不显示生成的“// File: 路径”标记。只删除证据清单中明确的生成标记，真实源码中的同样文字、注释、说明字符串和闭合符均保留。完整有序文件清单、文件边界及行映射在支撑记录中保存；最终Word回读后去除编号、合并显示折行，与冻结源码逐行比较，保留缩进及字符串空白。源程序量统计原程序物理行，不能填写编号数、展示折行数或提交页数乘50。

不足60页且确认候选已用尽时提交全部；超过相应范围时按当前受理要求处理连续前后页。不要为了沿用案例页数而改选材或凑内容。

## 共同页眉页脚及交付检查

两份文件统一名称版本页眉，页号在右侧，著作权人页脚居中，通常均9磅宋体、黑色。页码必须是可正确显示的字段，不能由继承的居中制表位把页码挤到中间；必要时使用相对页边距的右对齐位置制表符。主题字体统一宋体/Times New Roman，代码正文仍保留Consolas。

交付前核对封面与目录、全部章名、流程与模块图、真实截图与图注、无附录及残留引用、代码50行及每页重编、页眉页脚、源码逐行一致和实际分页。封面/目录/含图/结束页分别记录，不把所有图文页宣称为普通正文30行。渲染覆盖每一页，联系表看整体，原尺寸查看文字密集、边界和异常页。OpenXML错误为0不能替代这些检查。

修订后同步实际代码页数至申请表TXT/MD和当前清单、报告。原估算保留为历史；新旧正式文件避免混放，备份与修订差异另存analysis目录。文件已按格式完成但身份或权属材料待补录时如实列出，不保证登记批准。
