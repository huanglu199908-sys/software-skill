# 阶段交付与验收

| 阶段 | 应有成果 | 完成依据 |
| --- | --- | --- |
| 从零了解需求 | 用户、事务频率、现有办法、合法输入、输出用途、资源和约束 | 有实际来源；未知明确标出，不创造事实 |
| 选题 | 可比较候选：业务价值、输入输出、现有办法、算法空间、数据与成本、独立性 | 用户已选择；有意义且可交付，名称变化不等于新软件 |
| 方案设计 | 闭环、模型/标识、模块、界面状态、校验、算法/基线/不变量、回退、导出和验收 | 核心承诺都有可独立检查的期望，不只有术语或草图 |
| 实行 | 源码、依赖、启动入口、样例、真实验收、异常处理与实验记录 | 输入到输出真实跑通，关键不变量正确，实验不隐藏负向结果 |
| 撰写 | 业务理解、申请事实、选材与快照、手册、真实截图、生成输入、Word/TXT | 与实际软件一致，缺失事实/图片明确列出 |
| 审核 | 分项问题、来源、哈希、真实页数和未验证项 | 分开判断真实性、完整性、权属、排版与法规，不用单一“通过” |
| 修改润色 | 问题ID—原因—修改—复验—状态，最终有效文件 | 最终哈希回读与全页检查；剩余事项如实交付 |

`init_project.py`创建的是记录框架，不是软件。不要为填模板发明事实。用户已提供信息不重复问，不要求每个小项目固定数量设计文档；先做可运行纵向流程，再扩展确认范围。

建立功能—实现文件—验收—真实页面—手册章节对应表，开发中更新。截图、接口或数据缺失时继续不依赖它们的工作，不能把核心未实现改称已完成。只有合成数据时声明尚未验证真实收益。

每轮审查取值为通过/失败/未验证/不适用，带实际证据和范围。没有真实排版时不填写估算为实测，不预设固定修订轮次或登记获批。
