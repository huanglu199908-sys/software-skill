# 三个项目的复盘与可复用经验

这是截至 2026-10-17 的项目案例，不是新项目的默认参数，也不是登记已获批的记录。案例不包含自然人证件号码或协议内容。

## 三种业务与算法路线

| 软件 | 实际用途 | 已实现的算法机制 | 最关键的验证 |
| --- | --- | --- | --- |
| 多源表格自适应核对软件 | 两份办公表格的一对一记录核对、差异定位与人工复核 | 字段画像、自适应候选通道、多特征评分、缺失归一化、分量内分配、歧义转复核 | 候选召回、匹配质量、一对一约束；结合自动覆盖率解释自动精确率 |
| 增量式办公台账数据质量检查软件 | 连续版本台账的质量检查、问题跟踪和完整报告 | 稳定身份与双摘要、字段—规则依赖、重复键成员和分组状态维护、兼容性回退 | 与全量的完整结果及证据一致；删除/跨组/等值原文变化和失败恢复 |
| 高校监考任务约束排班与局部调整软件 | 考务初排、请假后调整、核查与发布 | 约束求解、合法初解提示、稳定岗位、区域外常量、分层扩展修复、独立核查与版本一致发布 | 所有硬约束合法；小规模独立枚举；换岗数量与局部最优范围 |

共性是“输入—算法—可解释结果—人工决定—保存/导出”，并在需要时加入历史与恢复。它们的不同主要在核心任务和状态模型，不能把同一套界面换标题当作新的方向。

## 实验里真正学到的事

**表格核对：** 1000行合成输入中，自适应方法比固定分块产生更多候选并提高本样例召回，也更耗时；部分消融与完整方法结果相同。因而不能写成所有机制都贡献显著或速度普遍更快。原README仍留有V0.1及未生成材料的历史说明，提示未来必须核对版本和最新事实，不能直接复制旧文档状态。

**台账检查：** 100次合成端到端运行未观察到全量/增量结果不一致，重算数量显著减少，但增量在部分规模/格式下更慢。读取、规范化、基线加载、写库及完整导出仍有全数据成本；减少规则重算不等于同比减少整个软件耗时。默认20%回退阈值遇到26.7%演示变更会走全量，手册必须说明真实策略。

**监考排班：** 53项自动验收通过；72次合成实验中56次有完整合法候选、16次UNKNOWN。局部模型优化从“全域变量再固定”改为“只对释放岗位建变量，外部直接代入常量”，但仍保留全局硬条件。局部OPTIMAL不代表全域最少换岗，未完成方法也不能参加同口径的完整流程加速比较。

这些是特定输入与环境下的观察。没有真实单位试用的项目不能写已在单位业务中验证，不能把合成结果包装为真实办公或学校效益。

## 修订暴露的检查缺口

| 发现 | 对以后流程的改进 |
| --- | --- |
| 原表格代码Word漏独立注释、说明字符串和末尾闭合标记 | 冻结完整文件，最终Word回读并逐行映射核对，尤其检查每个文件末尾 |
| 折行后页数变化，申请表仍是估算 | 分开统计源码与展示行，最终回填实测页数 |
| 普通手册页不足30行 | 做真实视觉行数审计；用合理排版与必要操作说明修复 |
| 删除附录后目录/引用可能残留 | 将附录正文、目录、引用和尾页作为同一修订范围检查 |
| 表后空段落造成空白尾页 | 渲染到最后一页，不能只查结构或前几页 |
| 模板页码居中、刷新后节点顺序异常 | 在最后字段刷新后再做结构和视觉复验 |
| 工具参考版本与实际安装版本不同 | 记录用户选择与实际版本，逐份验证，恢复时不重复询问 |
| 草稿反复确认、历史结果混淆 | 保存范围明确的确认记录、文件哈希、有效版本与下一步 |

最新工作流进一步收紧了历史审计的弱点：旧版“删除全部空白再比较”的方法不能发现缩进或字符串空白错误；新流程保留字符语义，以映射后的完整源码行为准。
