# 状态、证据与恢复工作

## 单一项目记录

默认在用户指定的项目内维护：

```text
项目/
  实际源码及启动入口
  tests/                        按项目技术栈组织
  docs/ 或 设计文档/             实际需要的设计和验收说明
  experiments/                 有性能主张时保留原始记录
  流程记录/
    当前状态.json
    确认记录.md
    功能证据对应表.md
    问题与修订记录.md
  软件著作权申请资料/
    草稿/
    截图原始/、截图/
    正式资料/
    审查记录/日期或修订号/
```

尊重现有布局，不为迁就这个示意搬动用户文件。每个新软件独立目录；公共组件可复用，但要记录来源和许可，不复制旧软件登记主体。

`当前状态.json` 至少记录：项目根目录、当前阶段、软件名称/版本的确认状态、最近真实用户决定、代码证据清单、当前有效正式文件、工具版本、剩余问题和下一步。日期用实际日期，不能把旧例子的完成日期作为新项目日期。

每项证据包含相对路径、SHA256、产生时间、来源命令/输入、支持的结论和已知限制。完整身份号码留在用户指定的本地登记文件；状态、测试日志、分享包和技能示例只记录“已确认/待补录”，不复制敏感值。

## 三种状态不能混淆

- **决定已确认：** 用户选择或事实口径已明确。保留原回复摘要、适用项目和范围。
- **内容已审阅：** 具体草稿内容及其指纹被确认；内容实质变化会使其过期。
- **检查已完成：** 指定哈希的产物完成某种检查，不能沿用到另一个文件或后来修订的版本。

重启后先读这些记录和当前文件，而不是重新发出整套问卷。用户的“按刚才报告修正”授权对应报告列明的修订，不自动授权新的权属变化。

## 变更影响

| 变更 | 应重新检查 |
| --- | --- |
| 名称、登记版本、权属 | 申请表、封面、页眉、正文、文件名、协议引用与用户确认 |
| 算法、输入输出或业务行为 | 相关测试与实验、业务理解、手册、截图、源码材料 |
| 仅文案/附录删除/字体页距 | 文本引用、目录、分页、图注、页数及最终哈希 |
| 仅证件补录 | 当地填写字段、完整性与授权范围，不重复跑算法 |
| 后端版本改变 | 环境记录、当前正式产物结构、分页与预览 |

修订前备份指定文件并保存哈希，修订后形成“问题—证据—动作—复验—状态”。发现反复失败时定位原因或明确缺少能力，不能把未检项写成通过。完成后列出唯一当前有效版本，历史证据用日期/修订号区分。
